# Maintaining the MySQL fork

This fork tracks [umami-software/umami](https://github.com/umami-software/umami) and adds
MySQL 8.0+ support. It is built to need attention only when an upstream change breaks MySQL.

## How MySQL support works

Upstream query files are left untouched. Everything MySQL-specific lives in a few places:

| Path | What it does |
| --- | --- |
| `src/lib/mysql/dialect.ts` | Translates the raw PostgreSQL SQL in `src/queries/sql` to MySQL at runtime. |
| `src/lib/mysql/client.ts` | Plugs the translator into Prisma, sets the connection session, normalises results. |
| `src/lib/prisma.ts`, `src/lib/db.ts` | Small hooks: driver adapter choice, `mysql` database type, Prisma search options. |
| `db/mysql/schema.prisma` | Generated from `prisma/schema.prisma` by `pnpm mysql:schema`. Never edit by hand. |
| `db/mysql/migrations` | MySQL migrations, generated by `pnpm mysql:migrations:create`. |
| `scripts/mysql/` | Schema generator, migration tooling, DB checks, parity runner, coverage check. |
| `tests/mysql/parity/` | Parity suite: dataset, query cases, comparison. |

The build picks the Prisma provider from `DATABASE_URL` at build time, so one build (or image)
serves one database type.

## The safety net

Every push and pull request runs `.github/workflows/mysql.yml`:

1. **Unit tests** (`pnpm test`), including the translator tests in `src/lib/mysql/dialect.test.ts`.
2. **Schema check**: `db/mysql/schema.prisma` matches `prisma/schema.prisma`.
3. **Coverage check** (`pnpm mysql:coverage`): every query function in `src/queries/sql` that runs
   SQL on PostgreSQL has a parity case, and no raw SQL appears elsewhere in `src` unreviewed.
4. **Migration check**: `db/mysql/migrations` produces exactly `db/mysql/schema.prisma`.
5. **Parity suite** (`pnpm test:mysql:parity`): seeds the same data into scratch PostgreSQL and
   MySQL databases through umami's own write functions, runs ~430 query cases on both and fails
   if MySQL returns anything different. Rows that only differ in the order of tied values pass.
6. **API suite on MySQL** (`pnpm test:api:mysql`): the upstream end-to-end API tests against the
   MySQL Docker image.

## Upstream sync

`.github/workflows/upstream-sync.yml` runs nightly (and on demand from the Actions tab):

1. Merges upstream `master` into a `upstream-sync/<sha>` branch. A `pnpm-lock.yaml` conflict is
   resolved by regenerating the lockfile.
2. Regenerates `db/mysql/schema.prisma` and, if upstream changed the schema, a MySQL migration
   named after upstream's newest PostgreSQL migration.
3. Runs the full check list above on the branch.
4. If everything passes, fast-forwards `master` and publishes the Docker image.
5. If anything fails, opens one issue labelled `upstream-sync` (later failures comment on it) and
   closes it automatically once a sync lands.

### One-time setup

- **Actions permissions**: Settings → Actions → General → Workflow permissions →
  "Read and write permissions".
- **`SYNC_TOKEN` secret (recommended)**: the default Actions token cannot push changes to
  `.github/workflows`, so a sync that includes upstream workflow changes fails at the push.
  Create a fine-grained personal access token for this repository with *Contents* and
  *Workflows* read/write, and save it as the `SYNC_TOKEN` repository secret.
- **Branch protection**: if you protect `master`, allow the sync token to push to it, or the sync
  will stop at the fast-forward step.
- **Image visibility**: after the first publish, make the `umami-mysql` package public under the
  repository's Packages if others should pull it.

## When the sync issue opens

The issue says which stage failed and links the run.

**Merge conflicts.** Upstream changed lines this fork also changed (usually `src/lib/prisma.ts`,
`src/lib/db.ts`, `Dockerfile`, `prisma.config.ts` or `package.json`).

```bash
git remote add upstream https://github.com/umami-software/umami.git  # once
git fetch upstream
git checkout -b upstream-sync/manual origin/master
git merge upstream/master          # resolve, keeping both sides' intent
pnpm install
pnpm mysql:schema
SHADOW_DATABASE_URL=mysql://root:pw@localhost:3306/umami_shadow \
  pnpm mysql:migrations:create <newest prisma/migrations name>
```

Then open a pull request; CI runs the full check list.

**Coverage check failed.** Upstream added a query. Add cases for it to
`tests/mysql/parity/cases.ts` (look at a similar query's cases), or, for a query that cannot
run on relational databases, list it in `tests/mysql/parity/uncovered.json` with the reason.

**Parity failed.** The run summary lists each failing query with the MySQL error or the first
difference. Reproduce locally:

```bash
PARITY_POSTGRES_URL=postgresql://postgres:pw@localhost:5432/postgres \
PARITY_MYSQL_URL=mysql://root:pw@localhost:3306/mysql \
  pnpm test:mysql:parity --filter <query name> --keep-results
```

Results land in `tests/mysql/parity/.results`. Set `LOG_QUERY=1` to print each translated query.
Fix the translation in `src/lib/mysql/dialect.ts` and add a unit test for the new construct in
`dialect.test.ts`. If a query cannot be translated generally, give it a MySQL-specific
implementation: `runQuery` prefers a `[MYSQL]` entry over `[PRISMA]`.

**Schema or migration failed.** Regenerate as in the merge steps above. Analytics tables
(case-sensitive collation) are listed in `CASE_SENSITIVE_TABLES` in `scripts/mysql/migrations.js`;
add new upstream analytics tables there.

## Local development

```bash
docker run -d --name mysql8 -e MYSQL_ROOT_PASSWORD=pw -p 3306:3306 mysql:8.0
docker run -d --name pg15 -e POSTGRES_PASSWORD=pw -p 5432:5432 postgres:15-alpine

DATABASE_URL=mysql://root:pw@localhost:3306/umami pnpm build && pnpm start
pnpm test:api:mysql   # API suite against the MySQL Docker image
```
